## 저장 시점의 값이 바뀌는 이유

주문을 확정할 때 품목 목록을 감사 이벤트에 담는다고 해 봅시다. 이벤트 이름을 바꾸기 위해 data class의 `copy()`를 호출해도 생성자 프로퍼티가 참조하는 목록은 공유됩니다. Kotlin의 `List`는 읽기 전용 인터페이스입니다. 그 목록을 만든 쪽에 `MutableList` 참조가 남아 있으면 나중에 추가한 항목도 이벤트에 보일 수 있습니다.

Java record도 구성 요소가 가리키는 목록을 자동 복사하지 않습니다. Java에서 `List.copyOf`로 구조를 분리할 때처럼 Kotlin에서는 기록을 생성하는 경계에서 `toList()`로 목록을 분리할 수 있습니다. 두 방법 모두 목록 안의 객체까지 복제하지는 않습니다. [Kotlin data classes](https://kotlinlang.org/docs/data-classes.html), [Java List API](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/util/List.html)

## 저장 경계에서 두 번 확인하기

```kotlin
data class OrderEvent(val state: String, val items: List<String>)

fun main() {
    val source_items = mutableListOf("book", "pen")
    val pending = OrderEvent("pending", source_items)
    val shared_event = pending.copy(state = "confirmed")
    val saved_event = pending.copy(
        state = "confirmed",
        items = pending.items.toList(),
    )

    source_items += "notebook"
    check(shared_event.items == listOf("book", "pen", "notebook"))
    check(saved_event.items == listOf("book", "pen"))
    check(saved_event.state == "confirmed")
}
```

| 복사 대상 | 원본 변경의 영향 | 경계에서 할 일 |
| --- | --- | --- |
| 목록을 공유하는 이벤트 | 항목 추가와 삭제가 보임 | 생성 시 목록 구조 분리 |
| 문자열로 구성된 별도 목록 | 원본에 추가한 항목이 보이지 않음 | 변경 이후에도 저장값을 비교 |
| 가변 객체를 담은 별도 목록 | 공유 원소의 필드 변경이 보임 | 원소도 불변 값으로 변환 |

Spring에서 트랜잭션 커밋 뒤에 이벤트를 처리한다면 발행 전에 필요한 필드를 불변 값으로 옮깁니다. 품목이 JPA 엔티티라면 목록만 복사해도 엔티티는 그대로 공유됩니다. 품목 코드와 수량이 필요하다면 그 두 필드를 담는 값으로 변환하고, 테스트에서는 발행 후 원본 목록과 원소를 각각 바꿔 봅니다. 동시에 변경되는 목록에서 일관된 스냅샷을 얻으려면 복사 시점의 소유권이나 동기화도 따로 정해야 합니다.
