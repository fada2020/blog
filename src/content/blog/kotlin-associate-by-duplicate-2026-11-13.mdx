Spring Boot 서비스에서 상품 조회 결과를 코드별로 찾아 쓰기 위해 목록을 맵으로 바꾼다고 가정합니다. 같은 코드가 두 번 들어오면 그중 어떤 행을 남길지부터 결정해야 합니다. 중복이 조인 오류인지, 여러 이력 중 하나를 고르는 정상 상황인지에 따라 구현이 달라집니다.

2026년 11월 13일 기준 Kotlin 최신 안정 버전 2.4.21과 표준 라이브러리 계약을 확인했습니다. [공식 릴리스](https://github.com/JetBrains/kotlin/releases/tag/v2.4.21), [associateBy API](https://kotlinlang.org/api/core/kotlin-stdlib/kotlin.collections/associate-by.html)

## 같은 키는 마지막 입력이 남는다

`associateBy`는 선택한 키를 맵에 저장합니다. 여러 원소에서 같은 키가 나오면 마지막 원소의 값이 남습니다. 여기서 마지막은 입력 순서입니다. 업무상 최신값을 고르려면 버전이나 수정 시각을 명시하고 동률 처리도 정의합니다.

```kotlin
data class Product(val code: String, val label: String)

fun main() {
    val rows = listOf(
        Product("A", "기본"),
        Product("B", "유지"),
        Product("A", "수정"),
    )
    val labels = rows.associateBy({ it.code }, { it.label })
    check(labels == mapOf("A" to "수정", "B" to "유지"))
    check(rows.reversed().associateBy { it.code }.getValue("A").label == "기본")

    val grouped = rows.groupBy { it.code }
    check(grouped.getValue("A").map { it.label } == listOf("기본", "수정"))

    val error = runCatching { index_unique(rows) }.exceptionOrNull()
    check(error is IllegalArgumentException)
    check(error.message == "Duplicate code: A")
    check(index_unique(rows.take(2)).keys == setOf("A", "B"))
}

fun index_unique(rows: List<Product>): Map<String, Product> = buildMap {
    for (row in rows) {
        require(row.code !in this) { "Duplicate code: ${row.code}" }
        put(row.code, row)
    }
}
```

## 조회 결과의 의미에 맞는 변환

| 입력 계약 | 변환 | 코드 A의 결과 |
| --- | --- | --- |
| 뒤의 행이 앞의 행을 갱신 | `associateBy` | 수정 |
| 같은 코드에 여러 행 허용 | `groupBy` | 기본, 수정 |
| 코드마다 반드시 한 행 | 중복 검사 후 저장 | 예외 |

Java의 두 인자 `Collectors.toMap`은 중복 키에서 `IllegalStateException`을 던집니다. Kotlin으로 옮기면서 `associateBy`를 사용하면 같은 입력이 정상 처리될 수 있습니다. 기존 서비스가 중복을 감지했다면 실패 동작을 보존하고, 그 실패를 API가 어떻게 처리하는지도 기존 경계에서 확인합니다. 예제의 예외 타입은 중복 입력을 거절하는 새 함수의 계약입니다. [JDK 21 Collectors](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/util/stream/Collectors.html), [Kotlin groupBy API](https://kotlinlang.org/api/core/kotlin-stdlib/kotlin.collections/group-by.html)

중복이 조인으로 생긴다면 먼저 조회 결과의 단위를 확인합니다. 예를 들어 상품과 카테고리를 조인해 상품 하나가 여러 행에 나타날 수 있습니다. 카테고리를 모두 보여주는 응답이라면 상품별로 행을 묶습니다. 코드의 유일성이 저장소의 규칙이라면 DB 제약과 조회 결과 검사를 각각 적용할 수 있습니다.
