## .NET 11은 지원 기간부터 확인합니다

.NET 11 안정판은 2년 지원의 STS입니다. Microsoft는 C# 15의 유니언 타입과 닫힌 계층, ASP.NET Core의 비동기 검증과 OpenAPI 3.2 지원을 소개했습니다. 같은 날 .NET 8과 9의 지원도 종료됐습니다.

Spring 서비스의 JDK를 교체할 때처럼, 빌드 SDK와 운영 런타임 버전을 각각 확인해야 합니다. OpenAPI 생성기를 쓰는 팀이라면 문서 생성 성공에 더해 기존 소비자가 새 명세를 읽고 클라이언트를 다시 생성할 수 있는지 확인합니다. [Microsoft .NET 11 발표](https://devblogs.microsoft.com/dotnet/announcing-dotnet-11/)

## Firefox 160은 응답 헤더 테스트에 영향을 줍니다

Firefox의 WebDriver BiDi는 네트워크 이벤트에서 여러 `Set-Cookie` 응답 헤더를 각각 별도 항목으로 전달하도록 고쳤습니다. 기존 테스트가 결합된 헤더 하나를 기대했다면 브라우저 업데이트 후 쿠키 설정이 성공해도 단언이 실패할 수 있습니다. 세션과 설정 쿠키를 동시에 내려주는 테스트에서는 두 이름과 각 속성을 개별 검증합니다.

Firefox 160의 `WebTransport` 생성자는 세션 연결 요청에 커스텀 헤더를 넣는 옵션도 지원합니다. 다른 브라우저까지 지원해야 하는 서비스는 같은 옵션의 지원 여부를 브라우저별로 확인해야 합니다. [Mozilla Firefox 160 개발자 릴리스 노트](https://developer.mozilla.org/en-US/docs/Mozilla/Firefox/Releases/160)

## CNCF Sandbox 편입은 프로젝트 단계의 변화입니다

CNCF는 OpenShell과 Agent Substrate의 Sandbox 편입을 발표했습니다. 에이전트 실행 환경을 시험한다면 일반 앱 배포 때와 마찬가지로 서비스 계정, 외부 네트워크 접근, 감사 로그의 운영 책임을 먼저 정합니다. 가령 샘플 작업에는 읽기 전용 파일과 허용된 목적지 하나만 주고, 작업별로 접근 권한과 기록을 확인할 수 있습니다. CNCF의 Sandbox 표기는 프로젝트 단계입니다. [CNCF 공식 발표](https://www.cncf.io/announcements/2026/11/10/cncf-hits-major-milestones-with-global-community-growth-record-industry-investment-and-a-new-generation-of-projects-to-build-ai-systems-in-production/)

## Gemini Decisions API는 후보별 점수를 돌려줍니다

`gemini-decision-1`은 입력을 바탕으로 미리 정의한 후보를 평가합니다. 가령 문의를 결제·배송·직접 검토 중 하나로 분류할 수 있습니다. Google 공지의 가격은 입력 100만 토큰당 0.10달러이고 출력 과금은 없습니다. 발표 당시 AI Studio에서 사용할 수 있고, 공식 예제는 `v1beta`를 사용합니다. Google Cloud의 Gemini 지원은 발표 당시 예정 상태입니다.

결과 처리 코드에서는 신뢰도 점수가 낮거나 API가 지연되면 직접 검토로 보낼 수 있습니다. 시험 데이터의 오분류율과 직접 검토로 넘어가는 비율을 함께 기록하면 라우팅 기준을 정하기 쉽습니다. [Google Gemini Decisions API 발표](https://blog.google/innovation-and-ai/technology/developers-tools/gemini-decisions-api/)

## PostgreSQL은 현재 메이저 버전의 패치부터 확인합니다

18.7, 17.12, 16.16, 15.20, 14.25가 공개됐습니다. 14.25는 PostgreSQL 14의 마지막 릴리스이며, 19 RC 2는 별도의 출시 후보입니다. 운영 서비스에서는 현재 메이저의 목표 패치 버전과 공식 공지의 배포 후 조치가 해당하는지를 확인합니다. 관리형 DB라면 공급자 콘솔에 표시되는 실제 적용 가능 버전도 확인해야 합니다.

점검 기록에는 업데이트 전후 `SHOW server_version` 결과와 주요 읽기·쓰기 테스트를 남길 수 있습니다. 14를 쓰는 경우에는 최신 패치를 적용한 시점과 지원 중인 메이저로 이전할 일정을 각각 적어 두면 지원 종료 대응을 추적하기 쉽습니다. [PostgreSQL 공식 업데이트 공지](https://www.postgresql.org/about/news/postgresql-187-1712-1616-1520-1425-and-19-rc-2-released-3442/)
