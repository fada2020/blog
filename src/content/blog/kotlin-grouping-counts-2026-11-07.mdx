운영 화면에서 주문 상태별 건수를 보여 주고, 장애 분석 화면에서는 상태별 원본 이벤트를 열어 본다고 가정해 봅시다. 두 화면이 같은 목록을 받더라도 필요한 반환 타입은 다릅니다. 아래 예제는 2026년 11월 7일에 확인한 Kotlin/JVM 안정 버전 2.4.21을 기준으로 합니다. [Kotlin 릴리스](https://kotlinlang.org/docs/releases.html)

## 화면이 요구하는 타입에서 시작하기

| 필요한 결과 | Kotlin | Java Streams |
| --- | --- | --- |
| 키별 원본 행 | `groupBy` → `Map<K, List<T>>` | `groupingBy(classifier)` |
| 키별 행 수 | `groupingBy().eachCount()` → `Map<K, Int>` | `groupingBy(classifier, counting())` → `Map<K, Long>` |

`groupBy`는 키별 목록을 만들고, `groupingBy`는 키를 선택하는 방법과 원본을 묶은 `Grouping`을 돌려줍니다. `eachCount()`를 호출하면 원소를 순회하면서 키별 개수를 누적합니다. 건수만 필요할 때는 이 경로로 키별 원본 목록을 만들지 않아도 됩니다. [Kotlin 컬렉션 그룹화](https://kotlinlang.org/docs/collection-grouping.html), [Java Collectors](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/util/stream/Collectors.html)

## 주문 이벤트 네 건으로 실습

```kotlin
data class OrderEvent(val order_id: Int, val status: String)

fun main() {
    val events = listOf(
        OrderEvent(101, "PAID"),
        OrderEvent(102, "FAILED"),
        OrderEvent(103, "PAID"),
        OrderEvent(102, "FAILED"),
    )

    val rows_by_status = events.groupBy { it.status }
    val counts_by_status = events.groupingBy { it.status }.eachCount()

    check(rows_by_status.getValue("PAID").map { it.order_id } == listOf(101, 103))
    check(counts_by_status == mapOf("PAID" to 2, "FAILED" to 2))
    check(counts_by_status.getOrDefault("PENDING", 0) == 0)
    check(emptyList<OrderEvent>().groupingBy { it.status }.eachCount().isEmpty())
}
```

실패 이벤트 두 건은 주문 102 한 건에서 나왔습니다. 장애 알림에 필요한 값이 ‘실패 이벤트 수’인지 ‘실패한 고유 주문 수’인지 먼저 정하세요. 후자라면 상태별 고유 주문 ID를 세어야 합니다. 상태 전이가 포함된 입력에서 ‘현재 실패 상태인 주문’을 세려면 주문별 최신 이벤트를 먼저 결정해야 합니다.

## Spring 서비스에 적용하기

이미 메모리에 있는 제한된 조회 결과라면 두 연산 중 반환 타입에 맞는 쪽을 선택할 수 있습니다. 결과가 큰 테이블에서 건수만 필요하면 DB의 `GROUP BY`로 집계해 애플리케이션으로 이동하는 행을 줄이세요. 응답에 모든 상태가 필요하다면 응답을 조립할 때 상태 목록을 순회해 누락 키를 0으로 채울 수 있습니다. 테스트에서는 빈 입력, 한 주문의 중복 이벤트, 조회 기간 경계를 각각 확인하세요.
